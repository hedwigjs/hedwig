# Audit note — `examples/advanced/` (2026-08)

- **Status:** informational
- **Date:** 2026-08-23
- **Companion to:** [`docs/content/guides/demo-architecture.md`](../guides/demo-architecture.md)

Snapshot audit of the reference stand before the broker migration
(`packages/broker`). Read this alongside the demo-architecture guide — the
guide describes *what* is in place, this note describes *why we didn't
touch some of it*.

## Refactors performed

- **Contracts split by domain.** `shared/contracts/src/topics.ts` now
  composes `TopicMap` from `domains/cart.ts | checkout.ts | notifications.ts
  | chat.ts | ui.ts`. Each domain owns its topics fully. Rationale: navigation,
  and structural readiness for `@hedwigjs/registry` codegen (one contract
  file per event, composed automatically).
- **`TopicPayload<K>` helper** exported from contracts. Reduces boilerplate
  where downstream code needs `TopicMap[K]`.
- **`NotificationKind` union promoted** to a real exported type instead of
  an inline literal in the topic payload — used by both the toast component
  and the backend push router.

## Things audited and kept as-is

Each item here is an intentional non-refactor. The reason matters more than
the item — the reason tells future contributors whether the trade-off still
holds.

- **State ownership is already three-tier and coherent** (singleton
  runtime, read-only projection, local React state). No cross-cutting
  cleanup needed. Documented in demo-architecture guide.
- **`chat.*` topics have no live subscribers.** They're an observability
  channel for future devtools. Do not gate them on a consumer.
- **Pill counter `− N +` is implemented three times** across
  `MenuPosition`, `MenuItemModal`, `CartList`. Not deduplicated because
  extracting a shared UI kit would introduce a workspace whose only value is
  "prevent copy-paste of 30 CSS lines" and confuse the demo's message.
- **CSS design tokens live in `shell/src/styles/reset.css`, referenced by
  MFEs without declaration.** Yes, this is an implicit dependency from every
  MFE onto the shell. Yes, in production you'd extract `@hedwig-demo/tokens`.
  Not done here to keep the workspace count from creeping up during audit —
  a real broker-first migration matters more than CSS hygiene.
- **Ad-hoc transport adapters** in `notifications` and `checkout` — not
  formalized because RFC-0001's adapter package doesn't exist yet. Once
  `@hedwigjs/adapter-*` ships, both files become one-liners.
- **`MockAiClient` left in codebase** despite `SseAiClient` replacing it.
  Kept as a reference implementation of the `AiClient` contract — useful
  when working offline or writing tests. Zero runtime cost.
- **Standalone MFE HTML entries** (`__CART_STANDALONE__` etc.) — dead
  weight in production, live scaffold for iframe-based per-MFE dev today.
  Preserved.
- **Header hardcodes "Иван" + avatar.** No plans for user-domain topics or
  auth in the demo. If a "logged in as X" story appears, add a `user.*`
  domain to contracts and wire it up.
- **`cart.checkout.requested.v1` lives in `cart.ts`, not `checkout.ts`.**
  Convention: a topic belongs to whoever emits it. Cart emits, so cart
  owns. Documented in the architecture guide.

## Small gotchas worth knowing

- **`req.on('close')` on POST SSE** (Node 15+) fires when body-parser
  finishes reading, not only when the client disconnects — killed the AI
  stream mid-response. Fix in `backend/src/routes/ai.ts`: listen on
  `res.on('close')` instead. Documented in comment.
- **`display: none` on a slot host still mounts the MFE.** Cart uses two
  MFE views (`Panel` + `HeaderTrigger`), both `activeWhen: () => true`;
  CSS decides which is visible. Cheap and predictable.
- **npm workspaces don't support nested workspace-roots.** All MFEs are
  registered flat in the root `package.json:workspaces` glob; the demo
  orchestrator (`examples/advanced/package.json`) is itself a leaf
  workspace with `concurrently` scripts, not a workspace-root.

## Ready for broker migration?

Yes. The next step (`packages/broker`) can proceed:

- Contract split provides stable seams for the codegen story later.
- `mock-bus` API surface is small and matches the target `@hedwigjs/broker`
  contract: `emit(topic, payload)`, `on(topic, handler, { replay? })`,
  `off(topic, handler)`, cross-realm singleton via `window`.
- No ad-hoc bus usage — all MFEs go through `mockBus`. A point-to-point
  import replacement is enough.
